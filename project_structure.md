# MathMax Project Architecture & Folder Structure

MathMax is a Next.js (App Router) web application designed for educational paper grading and student results management. The project uses JavaScript (not TypeScript) and follows a structured pattern with standard Next.js conventions.

Here is a comprehensive breakdown of the folder structure and all the key files within it.

## 📂 Root Directory (`d:\mathmax\`)
The root directory contains configuration files and standard Node.js/Next.js folders.

* **`package.json` / `package-lock.json`**: Define the project dependencies (like Next.js, React, Mongoose) and npm scripts (dev, build, start).
* **`next.config.mjs`**: Configuration file for Next.js behavior.
* **`.env.local`**: Stores environment variables (e.g., database connection strings, secret keys).
* **`jsconfig.json`**: Provides path aliases (like `@/` mapped to `./`) and JavaScript language service configurations.
* **`eslint.config.mjs`**: ESLint configuration for code linting and formatting rules.
* **`.gitignore`**: Specifies intentionally untracked files that Git should ignore (e.g., `node_modules`, `.next`).
* **`README.md`**: Project documentation and setup instructions.
* **`backend_plan.md.resolved` / `AGENTS.md` / `CLAUDE.md`**: Documentation, agent rules, and planning notes used during development.
* **`node_modules/`**: Contains all installed npm dependencies.
* **`.next/`**: The build folder generated by Next.js when running `npm run dev` or `npm run build`.
* **`public/`**: Static assets that can be served directly (e.g., images, global icons).
* **`uploads/`**: A local directory where uploaded files (like answer sheets or question papers) are stored before processing.

---

## 📂 App Directory (`app/`)
Because this project uses the Next.js App Router, the `app/` folder contains all routing, pages, layouts, and backend API endpoints.

* **`layout.jsx`**: The root layout wrapper applied to all pages. It typically includes the standard HTML/Body tags and global context providers.
* **`page.jsx`**: The main landing page of the application (e.g., a splash page or redirect router).
* **`page.module.css`**: CSS Modules for styling the root page.
* **`globals.css`**: Global CSS styles applied to the entire application.
* **`favicon.ico`**: The application icon displayed in the browser tab.

### 📁 `app/api/` (Backend Routes)
This directory acts as the backend server. Each subfolder corresponds to an API endpoint URL (e.g., `/api/auth`), containing a `route.js` file with `GET`, `POST`, `PATCH`, or `DELETE` handlers.

* **`analytics/route.js`**: Calculates and returns class performance, score distributions, and the student leaderboard for a specific paper.
* **`auth/route.js`**: Handles user registration, login, logout, and session validation (JWT or cookie-based).
* **`enrollments/route.js`**: Manages students joining subjects via join codes.
* **`export/route.js`**: Generates and downloads CSV reports of student scores.
* **`papers/route.js`**: CRUD operations for Question Papers and managing deadlines.
* **`reevaluations/route.js`**: Handles student requests for re-grading and teacher approvals/rejections.
* **`results/route.js`**: Fetches graded results and performance stats for students.
* **`subjects/route.js`**: CRUD operations for subjects taught by teachers.
* **`submissions/route.js`**: Handles file uploads (student answer sheets), fetches submissions, and triggers the AI grader.
* **`upload/route.js`**: A generic file upload handler that saves files to the `uploads/` directory.

### 📁 `app/auth/`
Contains the user-facing authentication pages.
* **`page.jsx`**: The Login / Sign Up UI.

### 📁 `app/student/` & `app/teacher/`
These define the routing for the student and teacher dashboards.
* **`app/teacher/dashboard/page.jsx`**: The main interface for teachers to manage subjects, upload papers, view analytics, and resolve re-evaluations.
* **`app/student/dashboard/page.jsx`** *(Assumed)*: The main interface for students to view enrolled subjects, upload answer sheets, and check grades.

### 📁 `app/components/` (Frontend UI)
Contains all reusable React components, split into logical categories.

* **`layout/`**: Structural components like `DashboardSidebar.jsx` and `DashboardTopBar.jsx`.
* **`shared/`**: Components and styles used by both roles (e.g., `dashboard.module.css`).
* **`ui/`**: Reusable generic UI elements like `Button.jsx`, `Badge.jsx`, `EmptyState.jsx`, `StatCard.jsx`, and `ScoreDistChart.jsx`.
* **`teacher/`**: Teacher-specific components:
  * `AnalyticsView.jsx`: The dashboard view showing stats and student leaderboards.
  * `EnrollmentManager.jsx`: Approving/rejecting student enrollments.
  * `PaperList.jsx` / `SheetsList.jsx` / `SheetDetail.jsx`: UIs to manage uploaded papers and graded answer sheets.
  * `ReevalQueue.jsx`: Interface to review student re-evaluation requests.
  * `SubjectGrid.jsx`: Visual grid of the teacher's subjects.
  * `UploadQPForm.jsx` / `UploadAnsForm.jsx`: Forms to upload question papers and answer keys.
* **`student/`**: Student-specific components:
  * `ResultDetail.jsx` / `ResultsList.jsx`: Viewing graded papers, scores, and AI feedback. Includes the re-evaluation request form.
  * `PapersView.jsx` / `StudentSubjects.jsx`: Viewing available subjects and assignments.
  * `UploadSheetForm.jsx` / `DirectUploadForm.jsx`: Forms for submitting answer sheets.
  * `StudentHome.jsx`: The main student dashboard view.
  * `ScoreTrend.jsx` / `DeadlineList.jsx`: Progress trackers and upcoming deadlines.

### 📁 `app/lib/` (Utilities & Logic)
Helper functions, integrations, and shared backend/frontend logic.

* **`api.js`**: The centralized frontend API client (using `fetch`) to communicate with the `/api` routes.
* **`auth.js`**: Backend authentication utilities (token generation, verification, and route protection middlewares).
* **`db.js`**: Establishes and caches the connection to the MongoDB database.
* **`grader.js`**: Contains the logic to process uploaded sheets and generate mock AI grades/feedback.
* **`deadlineUtils.js`**: Functions to parse dates, calculate time remaining, and return status colors.
* **`exportUtils.js`**: Logic to generate CSV files from JSON data.
* **`codeGen.js`**: Generates unique join codes for subjects/papers.
* **`mockData.js`**: Placeholder data structures used for testing UI layouts before the backend was fully connected.

### 📁 `app/models/` (Database Schemas)
Mongoose schemas defining the MongoDB database structure.

* **`User.js`**: Represents a user (Student or Teacher) with name, email, password, and role.
* **`Subject.js`**: Represents a class/subject created by a teacher.
* **`Paper.js`**: Represents an exam/assignment with a title, deadline, and a reference to its Subject.
* **`Submission.js`**: Represents a student's uploaded answer sheet, including their score, AI feedback, question-by-question breakdown, and grading status.
* **`Reevaluation.js`**: Represents a request by a student to re-grade a specific question.
* **`Enrollment.js`**: Represents a student joining a teacher's subject.

### 📁 `app/hooks/`
Custom React hooks for managing frontend state.
* **`useNavHistory.js`**: Manages browser history and back-button support within the Single Page Application dashboard views.
